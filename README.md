# 人格切换（astrbot_plugin_persona_switcher）

让**用户**在聊天里自己换人格，但只能换成**管理员在后台勾选过**的那几个。

- 后台可视化勾选：插件详情页里直接勾「哪些人格允许被用户切换」，不用手打 ID
- 用户侧指令：`/人格`、`/人格切换 2`、`/人格当前`、`/人格重置`
- **先假切换再确认**：切换指令不会立刻改人格，先问是否清空上下文；引用提示回复「是/同意」= 清空后切换，直接发下一句话 = 保留上下文切换
- 群聊投票：群里切换人格不再直接生效，改为发起投票；成员必须**引用提案消息**投「同意」，按群人数 2% 计算通过票数
- 会话级隔离：A 群切成猫娘，不影响 B 群和私聊
- 与 AstrBot 原生人格互通：WebUI「会话管理」里能看到同一个人格，下一条消息立即生效
- 零第三方依赖：只用 AstrBot 自带的 Persona / 会话存储，不需要 Redis、外部 API 或额外 Python 包

## 安装

要求 AstrBot **4.16 及以上**（4.x）。

仓库安装（推荐）：

```text
https://github.com/Geekertao-Studio/astrbot_plugin_persona_switcher
```

WebUI → 插件 → 从仓库安装，填上面的地址；或把本目录放进 `AstrBot/data/plugins/` 后重载插件。

装好后在插件列表里点开「人格切换」，进入「可切换人格」设置页勾选即可。

## 后台设置

插件详情页的可视化面板：

- **允许使用全部人格**：开启后不限制，任何人格都能切（默认开启，装完即可用）
- **可切换人格**：关闭「全部人格」后，只有勾选的人格会出现在用户列表里

同样的设置也在插件配置页里（`allowed_personas` 是人格 ID 列表），两个入口改的是同一份配置。

其他配置：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `admin_only_switch` | 关 | 只有管理员能切换，普通用户只能看列表 |
| `allow_private_chat` | 开 | 是否允许在私聊切换 |
| `allow_group_chat` | 开 | 是否允许在群聊切换 |
| `clear_context_on_switch` | 关 | 切换时清空当前会话上下文，避免旧人格的对话残留 |
| `confirm_context_clear` | 开 | 先假切换并询问是否清空上下文；关闭则直接切换 |
| `confirm_timeout_minutes` | 30 | 切换确认的有效期 |
| `show_prompt_preview` | 关 | 列表里附带人格提示词前 60 字（含私密设定时别开） |
| `max_list_items` | 20 | 聊天里一页最多显示多少条 |
| `group_vote.enabled` | 开 | 群聊是否走投票 |
| `group_vote.ratio` | 0.02 | 通过票数占群人数比例 |
| `group_vote.min_votes` | 3 | 最少通过票数 |
| `group_vote.max_votes` | 20 | 最多通过票数，0 = 不封顶 |
| `group_vote.default_threshold` | 5 | 群人数取不到时的默认票数 |
| `group_vote.timeout_seconds` | 300 | 投票时长 |
| `group_vote.count_proposer` | 开 | 发起人自动计 1 票 |
| `group_vote.require_quote` | 开 | 必须引用提案消息才算票 |
| `group_vote.keywords` | 同意/赞成/支持/+1/yes/agree | 赞成票关键词 |
| `group_vote.admin_bypass` | 开 | 管理员在群里可跳过投票 |

## 指令

| 指令 | 别名 | 说明 |
| --- | --- | --- |
| `/人格` | `/persona` `/人设` | 查看当前人格 + 可切换列表（默认入口） |
| `/人格 帮助` | — | 查看指令说明 |
| `/人格列表` | `/人设列表` | 列出可切换人格（当前那个会标出来） |
| `/人格切换 <编号或ID>` | `/人设切换` `/切人格` | 切换到指定人格，也支持直接 `/人格 2` |
| `/人格当前` | `/人设当前` | 查看当前会话的人格 |
| `/人格重置` | `/人设重置` | 清除会话人格，回到默认 |
| `/人格投票` | `/投票切换` | 查看本群投票进度；`/人格投票取消` 取消（发起人或管理员） |
| `/人格允许 <编号\|ID\|全部>` | — | 管理员：加入可切换列表 |
| `/人格禁止 <编号\|ID\|全部>` | — | 管理员：移出可切换列表 |

示例：

```text
用户：/人格
机器人：可切换人格：
        1. default — 你是一个乐于助人的助手。
        2. 猫娘 — 你是一只黏人的猫娘……
        3. 正经助手 — ……
        用法：/人格切换 <编号或人格ID>

用户：/人格切换 2
机器人（私聊）：【人格切换确认】PS-3F9A2C
                准备切换到「猫娘」。
                当前上下文可能残留旧人格，建议清空：
                · 引用本条消息回复「是」或「同意」→ 清空上下文后切换
                · 不引用，直接发下一句话 → 保留上下文并切换
                （30 分钟内有效）

用户：（引用提示）同意
机器人：现在以「猫娘」的身份继续聊。

或者：
用户：直接发下一句普通消息
机器人：保留上下文，切换到「猫娘」后继续回答。

群聊里发同一个指令则会变成投票：
机器人：【人格切换投票】PV-3F9A2C
        提议：把本群人格切换为「猫娘」
        通过票数：4 票（群人数 200，按 2.0% 计算，下限 3、上限 20）
        投票方式：引用本条消息并发送「同意」
        截止：5 分钟后
        发起人 小明 已计 1 票。

群成员（引用提案消息）：同意
机器人：【人格切换投票】PV-3F9A2C 通过（4/4 票），本群人格已切换为「猫娘」。
```

## 群聊投票规则

- 只有**群聊**走投票；私聊仍然是发起人直接切换（管理员在群里默认也能直接切，可用 `admin_bypass` 关掉）
- 通过票数 = `ceil(群人数 × ratio)`，再夹在 `min_votes` 和 `max_votes` 之间，且不超过群人数
  - 默认 `ratio=0.02`、`min_votes=3`、`max_votes=20`
  - 例：200 人 → 4 票；10 人 → 3 票；2000 人 → 20 票（封顶）
- 票必须**引用机器人那条提案消息**；引用别人的消息、或者直接发「同意」都不算
- 一人一票，重复发不算；提案人默认自动计 1 票
- 投票有效期默认 5 分钟，超时自动作废并提示
- 投票状态只存在内存里：AstrBot 重启后未完成的投票会消失，需要重新发起
- 投票通过后同样先假切换，按上面的「清空/保留上下文」规则在下一轮消息真正生效

## 与「现成插件」的区别

写这个插件前翻过 AstrBot 插件市场里的人格类插件（2026-11 数据）：

- `persona_plus`（约 1.2k 下载）：功能很全，但「谁能切哪些」主要靠指令/关键词，不是后台勾选
- `persona_switch` 系列（几十下载）：大多只能全量切换，或者要在配置里手打人格 ID 白名单
- 其余多为「按关键词/情绪自动切」或「陪伴向人格演化」，不是「管理员圈定范围、用户自主切换」

所以这个插件的定位很窄：**后台勾选范围 + 用户自助切换 + 会话级隔离**，不碰人格内容生成，也不接管对话流程。

## 和记忆插件一起用

- 清上下文清的是 AstrBot 的会话历史；人格 system prompt 本来就不在历史里，所以旧人格的说话内容不会靠历史带过来
- 长期记忆是另一个库，清上下文不会删它。`memory_companion` 不读 `_clean_ltm_session`，但会按 `persona_id` 给记忆分作用域：旧人格专属记忆理论上不召回，无 persona 的旧用户事实仍可能被召回
- 本插件的确认钩子 `priority=1000`，会在 `memory_companion` 的 `-20` 之前落实人格，并把新人格写进本轮配置快照，避免「切换那一轮仍按旧人格回答」

## 实现说明

- 读取人格：`PersonaManager.get_all_personas()`
- 切换：`ConversationManager.update_conversation(persona_id=...)`，同时写入会话覆盖
  （`agent.config.persona.persona_id`），所以 WebUI 与插件看到的是同一份状态
- 重置：清掉会话覆盖，并把会话的 `persona_id` 置空，回到全局默认
- 群投票：OneBot `get_group_info` 取群人数，`send_group_msg` 拿提案消息 ID；投票人的消息必须带 `Reply` 段且指向该 ID（或引用文本里含提案码）
- 设置存储：插件配置 `data/config/astrbot_plugin_persona_switcher_config.json`
- 没有常驻轮询或外部请求；只有投票期间的一个到期定时器

## 已知边界

- 只影响走 AstrBot agent / LLM 流程的回复；别的插件自己硬编码的提示词管不到
- 「重置」回到的是当前会话的默认人格（全局配置里的那个），不是插件另存的某个快照
- 人格 ID 就是 WebUI 里的人格标识；重命名人格后，白名单里的旧 ID 会失效，需要重新勾选
- 群成员数与提案消息 ID 通过 OneBot v11 API 获取；非 aiocqhttp 平台取不到时会回退到默认票数，并按提案里的投票码匹配引用
- 如果协议端不返回引用消息段，投票无法校验引用；可以把 `group_vote.require_quote` 关掉（不推荐，容易被刷票）
